## 任务

修复奖励编辑 GUI 中命令奖励无法正确添加的问题，并补齐“实际给予玩家的奖励物品可置空”的完整支持。

## 已确认现状

### 1. GUI 中“命令奖励”目前只会写入命令列表，不会切换奖励类型

- 文件：
  - `src/main/java/gg/fotia/crates/listener/GuiListener.java`
  - `src/main/java/gg/fotia/crates/crate/CrateManager.java`
- 当前行为：
  - 奖励编辑界面点击“命令奖励”按钮时，会调用 `addRewardCommand(...)`
  - 但新建奖励默认类型是 `ITEM`
  - GUI 中当前没有奖励类型切换入口
- 结果：
  - 通过 GUI 给新奖励添加命令后，配置里虽然可能有 `commands`
  - 但 `type` 仍然是 `ITEM`
  - 重新加载后该奖励仍按物品奖励解析，命令奖励无法真正生效

### 2. “清空奖励物品”目前只清掉配置节点，没有形成真正的“空奖励物品”语义

- 文件：
  - `src/main/java/gg/fotia/crates/crate/CrateManager.java`
  - `src/main/java/gg/fotia/crates/reward/ItemReward.java`
  - `src/main/java/gg/fotia/crates/listener/GuiListener.java`
- 当前行为：
  - GUI 中已有清空奖励物品入口
  - 但清空后只是移除 `item` / `extra-items`
  - 读取物品奖励时，若 `item` 不存在，会回退为 `display` 图标
- 结果：
  - GUI 无法把“实际给予玩家的物品”设置成真正为空
  - 对 `ITEM` 奖励来说，当前“清空”后仍可能变成发放显示图标
  - 若后续允许真正为空，还需要检查 `ItemReward.give(...)` 对空主物品的处理

## 本次实现计划

### 1. 修复命令奖励的 GUI 添加链路

- 在奖励编辑流程中补齐“命令奖励可生效”的类型处理
- 目标是让玩家通过 GUI 添加命令后，该奖励能被正确解析为 `COMMAND`
- 同时保证已有命令奖励在 GUI 中可继续追加和清空命令

### 2. 补齐“奖励物品可为空”的读取、保存与发放逻辑

- 允许 GUI 将奖励主物品和额外物品保存为空
- 读取奖励配置时，区分“未单独配置物品”与“明确设置为空”
- 发放 `ITEM` 奖励时，若实际物品为空，不应回退发放显示图标，也不应抛异常

### 3. 保持显示图标与实际发放物品的职责分离

- `display` 继续仅用于预览、动画和 GUI 展示
- `item` / `extra-items` 仅用于实际给予玩家的物品
- 不引入没有代码实现的虚假配置

## 待确认问题

### 1. 命令奖励的类型切换方式

当前有两种实现方向，需要你确认：

1. 在奖励编辑 GUI 中新增“奖励类型”切换按钮
- 优点：行为明确，后续也便于扩展 MONEY / EXPERIENCE
- 缺点：界面会多一个入口

2. 当玩家在 GUI 中给奖励添加第一条命令时，自动把该奖励类型切成 `COMMAND`
- 优点：改动小，符合你这次提到的问题
- 缺点：类型切换是隐式行为

### 2. 当 `ITEM` 类型奖励的实际物品为空时，期望行为

需要确认“为空”时的最终语义：

1. 允许保存为空，并且开奖时不给任何物品
2. 不允许 `ITEM` 类型为空，只允许 `COMMAND` / `MONEY` / `EXPERIENCE` 这类奖励没有实际物品

## 预期结果

- 通过 GUI 可以正确做出可生效的命令奖励
- 通过 GUI 可以把“实际给予玩家的奖励物品”设置为空
- 显示图标与实际发奖不再混用
- 不修改无关功能
